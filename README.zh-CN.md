# ConfigurationManager.zh-cn 2.14.0 · 玩家与开发者手册

这是 **客户端 BepInEx 插件**，为 ConfigurationManager 设置界面增加汉化、人工编辑、API 翻译、机翻和工作台。

> [!WARNING]
> API 翻译使用你提供的供应商账户。请求到达供应商后，即使超时、取消、返回无效内容或未通过译文校验，也可能扣费。工作台的请求和 Token 预算用于约束提交量，实际用量、价格和费用以供应商账单为准。建议先用少数条目试译，并在供应商后台设置消费上限。译文适用性由使用者复核。

## 选择与安装

| ZIP | 客户端运行时 | 配套服务端 |
| --- | --- | --- |
| `Mono-SPT4x` | Mono / BepInEx 5，SPT 3.11、4.0、4.1 | 服务端联动使用 SimpleTranslatorCS 对应的 4.0 或 4.1 包 |
| `IL2CPP-SPT5.0be` | IL2CPP / BepInEx 6，SPT5.0be | SimpleTranslatorCS 5.0be包 |

1. 先安装与游戏运行时匹配的 **ConfigurationManager 本体**。本汉化插件是附加插件，不能替代本体；Mono与IL2CPP DLL不能混用。
2. 关闭游戏并备份 `BepInEx/plugins/zh-cn` 和个人配置。将完整安装包解压到 **游戏根目录**，确认 `BepInEx/plugins/ConfigurationManager.zh-cn.dll` 与 `BepInEx/plugins/zh-cn/UI.json` 存在。Mono 的 SPT 3.11、4.0 和 4.1 使用游戏自带 Newtonsoft.Json。IL2CPP 包另附可直接使用的 CLR 版。依赖报错时运行 `说明与工具/检查并补齐依赖.ps1`。详见 [依赖说明](docs/DEPENDENCIES_2026-11-02.zh-CN.md)。
3. 只保留一个本插件DLL。升级保留自定义译文、活动术语表和cache中的原文基准；覆盖 `UI.json` 前合并个人改动。**安装新DLL后完整重启游戏**。
4. 按当前游戏绑定的热键打开 F12 设置。原版菜单在顶部显示 **汉化工作台**，若只见“汉化 ▸”，先展开工具栏。适配成功的 BetterBepInEx 菜单在左侧显示入口。

ZIP 首页的 `安装说明.txt` 提供快速上手步骤，`说明与工具/` 附 AI 与 Agent 汉化指南和依赖检查工具。

## BetterBepInEx 兼容

Mono 客户端会自动识别 BetterBepInEx，并检查当前菜单接口是否兼容。启用新菜单时，标题、筛选、搜索、已修改、按键绑定和 BetterBepInEx 自身设置可显示中文。左侧第一行是 **汉化工作台** 和 **鼠标抓取**，第二行是 **精翻 / API / 机翻** 的译文开关。这些按钮跟随 BetterBepInEx 的菜单缩放。点击 **鼠标抓取** 后，可点模组名、分类或配置项左侧的文字定位人工编辑，也可抓取由原版配置管理器绘制的自定义控件。若上游菜单重做导致适配失败，`BepInEx/LogOutput.log` 会记录未匹配的入口，可关闭 **使用新菜单** 回到原版 F12。

未安装 BetterBepInEx，或关闭其 **使用新菜单** 开关时，使用原版 F12 菜单和顶部工作台。BetterBepInEx 的 **菜单缩放** 调节模组设置页，汉化工作台 **外观 → F12 界面缩放** 调节汉化工作台及其弹窗。中英双语模式下，菜单自身按钮使用短中文标签，模组设置仍按双语显示。切换显示模式或应用译文时，新菜单会重新索引设置并清空本次的撤销／重做记录。BetterBepInEx 当前面向 SPT 4.1.x。

## 仅装客户端：F12 设置汉化

仅装客户端即可汉化插件名、分类、设置名、说明、枚举和已观测到的自定义控件。原版顶部的「人工 / AI 翻译 / 机翻」与 BetterBepInEx 左侧的译文开关使用同一份设置，切换后会刷新当前译文。

在「精翻」中可用鼠标抓取、编辑并保存译文。在「API」中选择供应商、填写 API 密钥和模型，自动获取列表失败时可手动输入。在「机翻」中选择官方接口或网页模式。首次可先选少量未翻译文本，检查结果后再批量运行。

| 板块 | 常用操作 |
| --- | --- |
| 精翻 | 用鼠标抓取或选定条目，核对原文与预览，点击「保存并下一项」。也可导出提示词，在外部完成翻译后回填。 |
| API | 选择模型与插件，保留「跳过已有有效汉化」，再选择翻译范围并开始。任务结果先看总览。 |
| 机翻 | 使用翻译供应商的官方接口，或复制到网页翻译服务后手动回填。 |
| 显示范围 | 切换中文、英文或双语，检查当前启用的译文层。 |
| 翻译更新 | 比较插件更新前后的原文，复核、更新或确认旧译文仍适用。 |
| 外观 | 调整工作台缩放、配色和鼠标抓取高亮。 |

精翻、网页机翻和「翻译更新」点击 **更换插件**，在独立窗口搜索名称、中文名或 GUID，点击结果直接切换。API 和接口机翻点击 **选择插件**，勾选后点击 **应用选择**。编辑插件和批量目标分别记忆，首次只默认选择当前插件。人工译文未保存时，切换插件、文本或抓取其他文本会先提示保存、放弃或取消。详见 [插件选择交互说明](docs/PLUGIN_SELECTION_2026-11-09.zh-CN.md)。

高级设置可调整输入/输出预算、批量、请求间隔、重试及请求/token上限。保留跳过已有有效汉化；已保存结果和相关请求缓存会复用。超时、断网、格式错误不自动重发，临时429/5xx重试可设0；强制重翻会再次消耗费用。token统计取决于供应商是否报告usage，字符数不是token数。

F12 与网页都会在正式开始前显示自费确认。首次使用需等「我已悉知」的 5 秒倒计时结束，可取消，或在确认时选「以后不再弹窗」。任务未开始或正在运行时都可点 **紧急停止 API**。工具会取消等待中的请求、阻止后续批次并保留已落盘的有效译文。停用期间若要重试，先明确恢复 API，再选择「跳过已有有效汉化」。服务端任务根据当前连接和权限取消；连接已断开时，重新进入工作台核对任务状态。

人工层优先于 AI，AI 优先于机翻。保存通常即时刷新 F12。尚未显示过的自绘控件需展开对应插件后收集，复杂第三方控件能否翻译取决于菜单是否暴露文字、语境和对应的绘制入口。像 `<color=grey>文字</color>` 这样的源文本，编辑时请保留标签及属性后再检查预览。可抓取的控件仍需在游戏中验证实际显示。

首次创建配置时，游戏分辨率达到 3840×2160 默认使用 200%。已有缩放设置保留。可在工作台 **外观 → F12 界面缩放** 手动调节，范围为 100%–300%。工作台、插件选择和术语窗口一起缩放，原版 F12 设置窗口也跟随缩放。小屏幕会限制实际缩放以保留操作空间。

API 任务结果默认显示摘要。在 **展开任务详情 / 错误日志** 点击 **定位本次翻译总览**，可查看任务结论、插件统计和失败原因。同编号的「翻译过程」与「翻译输入」JSONL 位于 `游戏根目录/API翻译日志/ConfigurationManager.zh-cn/`。文本输入框的分类、设置名与说明支持翻译，框内当前值和默认值不发送给 API，也不会被翻译结果覆盖（可能包含路径、JSON 或凭据）。如果这些名称或说明仍未翻译，请先核对同批任务总览里的校验失败。

## 内置术语编辑窗口

点击工作台顶端的 **术语表**，或在 F12 设置汉化的「API」页点击 **编辑本地 AI 术语表**。

独立窗口支持搜索、逐条新增 / 修改 / 删除 / 停用、整体开关、字符和条目上限、剪贴板导入 / 导出、校验及免费匹配预览。点击保存才写入 `BepInEx/plugins/zh-cn/glossary/eft.zh-CN.tsv`，旧文件自动备份；外部文件已变更时不覆盖。关闭有未保存提示，F12隐藏后草稿保留到本次游戏结束。

参考表只发送当前原文命中的词条，默认800字符/24条，最多占任务输入字符预算10%。保存由下一次任务读取，**不会自动付费重翻已有译文**。该窗口只编辑本地F12表，服务端游戏文本读服务器自己的表。完整操作、修复与文本格式见 [术语表使用说明](docs/GLOSSARY_EDITOR.zh-CN.md)。

## 配套服务端：游戏文本与Fika

安装SimpleTranslatorCS **1.14.0** 对应服务器目标后，进入工作台 **服务端游戏文本**。服务器负责扫描、请求供应商、保护标记校验和保存，客户端负责提交发起者的密钥、选项与文本、显示进度和校对。

检测到兼容的 SimpleTranslatorCS 后才显示服务端游戏文本。服务器启用 Fika 时，在 F12 填写服务端 `workbench-admin.jsonc` 里的 `adminKey` 并验证，两端工作台随之解锁。服务器未启用 Fika 时，普通玩家可用原有玩家模式。网页投稿进入候选审核，由管理员批准后发布。AI 平台密钥由供应商提供，在翻译任务中单独填写。服务端术语表由服务器运营者维护。

服务端任务的平台密钥会交给当前服务器，请只在可信服务器使用；管理员与任务密钥仅本会话保存，F12个人密钥可自行选择本机加密记忆。不要分享管理员密钥。

新版通过服务端发布通知同步正式译文，空闲时没有 `/workbench/live` 轮询。服务端和客户端都更新后才支持推送，旧服务端可手动拉取。同步不消耗 AI token。已经打开的游戏页面可能需重开，dialogue 遵循重启提示。更换 DLL 后需重启。

服务端文本板块缺失时核对是否两边都为本次修正版、服务端是否加载成功、目标4.0/4.1/5.0be是否正确、当前连接是否指向该服务器；再点击重新检测。仅装客户端时不显示该板块属于正常情况。

## 不使用 API

人工页可复制含必要语境和匹配术语的提示词，在对应AI网站手动处理，再回填JSON并校验；网页响应需自行复制，程序不会登录网站。也可直接安装/编辑人工词典。不使用AI时不会因为启用译文层、编辑术语或同步服务端文本而计费。

可以用文本编辑器离线修改包内的 TSV 范例，再导入 F12 或网页工作台。网页从 **打开网页** 一步进入，**快照与草稿** 内可刷新网页数据和应用草稿。详见 [网页工作台操作](docs/WEB_WORKBENCH.zh-CN.md)。

## 网页工作台与离线 CFG

1. 游戏内点击「打开网页」。如果关了游戏，也可双击游戏根目录 `网页汉化工作台/网页汉化工作台.exe`，打开同一安装此前导出的快照。首次使用网页前需安装 .NET 8 ASP.NET Core Runtime。
2. 游戏里在「快照与草稿」导出新快照，网页里点「刷新快照与回执」。网页编辑完保存草稿，再回 F12 点击「应用网页 F12 草稿」。若原文或同层译文已变，先刷新快照并重新核对。服务端草稿需通过游戏确认投稿和审核。
3. 如果只有本机 `.cfg` 文件，进入网页「离线 CFG」，选择文件、核对插件 GUID、预览或试译，再下载 `_API.jsonc`。把检查过的词典放入 `zh-cn/translations/`。离线流程只可取得文件记录的分类、配置名、说明与可识别选项。要翻译自绘或仅在游戏中生成的文本，请进 F12 采集。

普通关闭最后一个标签页会结束本机服务。「停止本地网页服务」供需要立即退出或覆盖程序文件时使用，点击后会关闭该工作台进程。升级前若旧版 `WebWorkbench` 仍占用 DLL，先停掉旧服务，再展开新版的 `网页汉化工作台` 整个目录。

## 路径、排错与资料

- 本机译文放在 `BepInEx/plugins/zh-cn/translations/`，按插件 GUID 和 `_Manual.jsonc`、`_API.jsonc`、`_MT.jsonc` 后缀归类。F12 人工校订另存为 `_Manual.overrides.jsonc`。内置界面使用 `zh-cn/UI.json`。
- 首次启动会复制已识别的旧译文。读取时优先使用新版扁平路径，其次是旧分层目录，再其次是 `zh-cn` 根目录的旧人工译文。同层文件不同时保留原件，按上述顺序取用。合并同一层前请备份，并核对发布词典和个人校订。
- 原文基准与历史：`zh-cn/cache`，不要为了清理日志而删除整个cache。
- 输入 / 进度 / 错误日志：游戏根目录 `API翻译日志/ConfigurationManager.zh-cn`；日志不写密钥，但输入日志含待译文本，分享前检查。
- 不生效时先检查中文/双语模式、译文层开关、人工覆盖、原文是否变化和是否观察到目标控件。请求失败时核对密钥、接口主机、模型及预算，再小批测试。
- [完整术语表手册](docs/GLOSSARY_EDITOR.zh-CN.md)、[版本数字约定](docs/VERSION_POLICY.zh-CN.md)。

反馈附包名、运行时、修正版日期、重现步骤及脱敏日志，不要附API或管理员密钥。

## 工作原理与二次开发

本插件在 BepInEx 加载后挂接配置菜单的设置收集、绘制和刷新。源标识使用插件 GUID、配置分组和键，按字段选择当前有效译文、英文原文或双语显示。源文本变化时可与基准比较。游戏原有设置值、默认值和持久化由对应插件处理。`zh-cn/UI.json` 供 F12 和 BetterBepInEx 菜单本身使用，其他模组的名称与字段进该模组的 GUID 词典。

网页服务只监听本机，读取 F12 导出的快照，写入经结构校验的草稿。游戏端再次检查当前原文、语境和已有译文再决定是否写入。服务端游戏文本走 SimpleTranslatorCS 的单独路由，按连接、权限和工作台能力决定可用操作。需要给另一台机器的 Fika 服务器处理翻译时，仍需要支持的客户端连接、服务器授权和匹配的 SimpleTranslatorCS 构建。

| 改动目标 | 从这里开始 |
| --- | --- |
| 制作或更新某个插件的词典 | 按 GUID 编辑 `translations/<GUID>_Manual.jsonc`。先核对原文配置，并在 F12 抽查名称、说明、枚举和双语；通常只需分发词典文件。 |
| 调整设置菜单或移植到新运行时 | `ConfigurationManagerZhCnPlugin.cs` 是入口，`UiLocalization.cs`、`BetterBepInExCompatibility.cs` 和 `ConfigurationManagerScale.cs` 处理菜单。按实际接口形状验证 Harmony 补丁和 GUI 事件。 |
| 调整词典合并、采集或更新 | `JsoncLocalization.cs`、`LocalizationModels.cs`、`TranslationTracking.cs`。同时核对新版路径、旧版 JSONC 和人工覆盖优先级。 |
| 调整 API 或网页 | `TranslationClients.cs`、`TranslationSafety.cs` 和 `Shared/` 管理请求、标记校验和预算。网页程序在 `tools/web-workbench/`，游戏交接在 `WebWorkbenchBridge.cs`。 |
| 改服务端联动 | 客户端从 `ServerTranslationFeature.cs`、`ServerWorkbenchClient.cs` 和 `ServerLocaleSynchronizer.cs` 入手，配套服务端按 SimpleTranslatorCS 版本构建与验证。 |

从源码维护时保留项目许可证及依赖声明。Mono 使用 .NET Framework 4.7.1 引用程序集和 SPT 3.11 的 BepInEx 5.4.22 基线。IL2CPP 使用 `net6.0`、对应 BepInEx 6 和 IL2CPP ConfigurationManager 引用。两个项目的游戏路径分别可通过 `MonoGamePath`、`Il2CppGamePath` 指定，IL2CPP 的 `ConfigurationManagerPath` 可单独指定。网页项目使用 .NET 8。打包入口需要按脚本所列的本机游戏目录准备依赖。配置、游戏 DLL、API 日志和个人译文请留在测试安装。构建和打包命令见 [发布包约定](docs/RELEASE_LAYOUT.zh-CN.md)。

### 用 AI 协助修改

1. 给 AI [专用指南](docs/AI_AGENT_GUIDE.zh-CN.md) 和目标源码或脱敏原文，说明你要制作词典、修改界面还是移植运行时。附上游戏版本、Mono 或 IL2CPP、是否启用 BetterBepInEx 及重现步骤。
2. 制作汉化时优先交给 AI 游戏导出的待译项、插件 GUID 和匹配术语，请它原样保留键、标记和配置标识。只改代码时，给出一项可验证的改动，例如「打开下拉菜单时在 200% 缩放下对齐触发按钮」。
3. 要求 AI 给出涉及文件、测试结果和仍需进游戏确认的场景。运行仓库 `tools/一键测试汉化工作台.cmd` 可生成中文报告。常规回归使用本地模拟供应商，实机仍需抽查窗口缩放、抓取控件和 Fika 的真实连接。
