# 本地网页汉化工作台

同一页面提供「F12 插件设置」和「服务端游戏文本」。本地插件设置从游戏导出快照后可离线编辑，服务端文本也可在网页直接连接后拉取。AI 与机翻需能访问所选择的供应商。F12 工作台继续提供游戏内采集、鼠标抓取、管理员审核及发布。

## 独立连接 SPT 服务端

1. 安装 .NET 8 ASP.NET Core Runtime，解压独立的「网页汉化工作台」ZIP，双击根目录的 `网页汉化工作台.exe`。无需游戏或 BepInEx。也可将完整压缩包解压到游戏根目录，从 F12 打开同一个工作台。
2. 服务器安装并启动兼容的 SimpleTranslatorCS。连接窗口默认填入 `https://127.0.0.1:6969`，点击「连接」后检测 Fika。本机未安装 Fika 时自动授权并拉取原文。安装了 Fika 时，输入 `workbench-admin.jsonc` 的 `adminKey`，再点「验证并连接」。远程地址需要受信任的 HTTPS 证书和管理员密钥。
3. 连接后查看缺译目录。在「服务端游戏文本」选择条目，人工编辑或调用本机翻译接口，校对后点「保存网页草稿」。点「发布已保存草稿」并确认后，服务端校验原文与修订号，保存并尝试热加载。服务端有变化时整批拒绝，重新拉取后请核对原草稿。
4. 下一批先点「重新拉取服务端原文」。关闭最后一个网页标签会停止本机服务。下次需重新输入管理员密钥，原文修订号匹配时可继续使用已保存草稿。普通 F12 玩家投稿仍通过游戏确认和管理员审核。

独立启动使用当前用户的 `LocalAppData/ConfigurationManager.zh-cn/网页汉化工作台`。直连草稿和检查点按服务端地址隔离，与 F12 游戏会话的玩家投稿分开。管理员密钥只存于当前连接内存。AI 密钥按原流程填入供应商字段，翻译请求从网页工作台发出。空闲时网页只读取本机状态。

开发时可传入 `--standalone 17834`，然后打开本机端口。目录来自服务端缺译接口，每份发布草稿最多 30 条。新版 SimpleTranslatorCS 会将同批网页 AI 草稿保存为一个 `来源A.来源B_API.jsonc`。文件名使用实际发布条目所属的来源，过长时保留名称前缀和校验短码。

## 启动

将独立网页包完整解压到游戏根目录后，在 F12 汉化工作台点「打开网页」，或双击根目录的 `网页汉化工作台.exe`。需要 .NET 8 ASP.NET Core Runtime。同一工作区只允许一个新版网页服务运行，同一构建的多个标签共用该服务。刷新页面会接续原有服务，关闭最后一个标签后约两秒退出。「停止本地网页服务」可立即退出。

从 GitHub 2.14.0 内置网页升级时，先在旧页面点「停止本地网页服务」，再解压独立包。对应游戏目录的内置服务仍在运行时，独立版会提示先退出。游戏快照、草稿和回执仍保存在 `BepInEx/plugins/zh-cn/web-workbench`。旧 F12 快照只支持单插件草稿，多插件翻译和保存需要先升级 F12 并刷新快照。

从源码运行时使用：

```powershell
dotnet run --project tools/web-workbench/WebWorkbench.csproj -c Release -- "C:\Games\SPT"
```

开发模式下打开 [本地工作台](http://127.0.0.1:17832/)。启动后请在 30 秒内打开页面，终端会在最后一个标签关闭后退出。若端口被占用，可在游戏路径后加一个端口号，再打开终端显示的地址。新版客户端 DLL 要与游戏运行时匹配，替换后需要重启。服务端投稿需要本次配套 SimpleTranslatorCS 构建。

## 离线 CFG 试用

1. 打开网页，点「离线 CFG」，选择一份 UTF-8 的 `BepInEx/config/*.cfg`。导入不需要游戏快照。核对页面识别的插件 GUID，修改 GUID 后点「重新读取」确认。
2. 查看分类、配置名、说明和能识别的枚举候选值。筛选框可缩小试译范围。调用 API 时发送待译字段及其分类、相关说明和匹配术语。实际配置值及默认值注释保留在本机。
3. 在页面查看结果，点「下载 JSONC」取得 `<插件GUID>_API.jsonc`。继续翻译会跳过当前页已成功的字段。译文暂存在本标签页，关闭前先下载。安装到游戏前核对内容并备份同名文件，建议先在没有同名词典的测试插件上试用。

运行时设置、自绘控件和无法确认的候选值可在游戏里用 F12 补采。离线入口只提供下载，游戏目录和现有词典由用户自行管理。

## 操作

1. 在游戏中打开 F12 → 汉化工作台 →「快照与草稿」，按需导出本机 F12 文本或当前服务器的玩家目录。F12 导出范围是当前客户端已收集的原文。安装或更新插件后重新采集，自定义动态文本留在游戏内处理。
2. 在网页选择工作区并刷新快照。F12 预览按插件和配置分类展示名称及说明。点击文字，在右侧修改对应字段，可切换汉化、英文和双语视图。预览根据快照与当前草稿显示文字，实际设置值和游戏内控件由对应插件控制。
3. 使用「精翻」时，点击一条原文在右侧逐项校订，保存到人工层。每次进入「API 翻译」需要等 5 秒并同意自费声明，才能使用供应商、模型和任务按钮。离线 CFG 中的「启用 API 翻译」采用相同的确认。模型可自行输入，也可点击「刷新」查询，预算和重试在「请求参数」中设置。
4. API 模式可在「来源」和「字段」中分别全选或勾选多项，配合搜索和「仅未翻译」缩小范围，再点「选中全部匹配（跨页）」。翻页时可取消任意条目，重新全选会继续尊重排除项。每次确认发送最多 30 条，成功的条目从队列移除，失败条目留待处理。下一批开始前会核对原文，切换服务器时会清空旧队列。当前会话内保存或发布草稿后，仍可继续剩余队列。
5. 顶部「更多」收纳术语表、离线 CFG 和更新检查。网页发起的 AI 翻译使用本机词表，仅附加命中项。F12 草稿可包含多个插件，同一份使用同一译文层且最多 100 条，应用时按插件写入各自文件。服务端每份限 30 条。
6. F12 在游戏中点击「应用网页 F12 草稿」。DLL 校验原文、语境和该译文层的上次值，写入后请求重建设置列表。服务端则点击「预览网页服务端投稿」，核对内容并确认，以当前会话的玩家身份进入审核。正式文本由管理员在现有 F12 工作台审核发布。

服务器切换或客户端重启后需要重新导出服务端目录，再按新目录核对未提交内容。F12 的「刷新网页 F12 快照」发布当前快照。网页的「刷新快照与回执」可立即读取，网页在前台且没有正在编辑的内容或任务时也会每五秒检查一次。游戏内的网页连接面板显示最近的磁盘草稿状态。草稿应用与玩家投稿仍需在游戏内确认。

## 安全边界

- 网页只监听 `127.0.0.1`。校验 Host、Origin、浏览器请求来源和本次进程生成的会话令牌。页面禁止被嵌入，插件原文和译文用纯文本渲染。
- 网页只访问所选安装下固定的工作台快照、草稿和回执。插件负责最终写入译文，当前版本和语境必须匹配。加载内容、运行接口及回填均有大小限制。
- API 密钥仅用于当前本机翻译请求。直连模式由 SimpleTranslatorCS 校验管理员密钥并按服务端修订号发布。游戏快照模式的网页投稿由 DLL 绑定当前连接并经游戏界面确认，服务端入口以玩家身份执行，通过已有玩家档案、开关、冷却和容量校验。
- 当前边界面向浏览器跨站访问及 Fika 玩家权限。它依赖 Windows 用户账户保护本地安装目录。同一 Windows 账户下已经能直接修改游戏文件的进程具备相应的文件访问权限。

## 联动检查与优先级

| 优先级 | 结果或后续工作 | 状态 |
| --- | --- | --- |
| P0 | `manual-exchange` 已对外声明，但 4.0 和新版路由中都缺少 `manual-submit` 注册。旧客户端的人工回填因此可能找不到服务端接口。 | 本轮补齐两套路由，并新增强制玩家身份的网页投稿路由。 |
| P1 | 自动同步曾只检查连接代数，地址或会话已经切换但定时检查尚未更新代数时，迟到结果可能落到新连接的语言表。 | 本轮在接收与主线程应用时重新校验实际连接。 |
| P1 | 原 F12 人工提交先写入，再读取目录，管理员还会继续拉取。写入成功后任一后续读取失败，界面可能报错而让用户误以为未提交。 | 待做。先返回写入回执，再单独记录刷新和同步状态。 |
| P1 | 当前网关以 SPT 玩家档案存在性校验玩家请求。Fika 场景应验证传入会话是否始终绑定真实在线用户，以及玩家提交开关、每人限制和任务归属。 | 待在双客户端环境验证。涉及运营权限的动作继续由服务端独立校验。 |
| P1 | 当前 RequestHandler 身份探测依赖 `Host` 和 `SessionId` 字段。若某个适配器改为属性或采用不同字段，会失去连接绑定。 | 网页投稿在身份不明时拒绝；待对实机适配器补探测和测试。 |
| P2 | 游戏快照和直连目录均使用明确的大小上限，分页发生在网页工作台。装大量 Mod 时应测量拉取时间、传输大小和内存。 | 可进一步增加服务端分页。 |
| P2 | 当前网页保留一份草稿，且重新导出后需人工核对旧稿。需要多人或多安装工作流时再增加草稿列表、按原文比对迁移和冲突界面。 | 待做。 |

F12 的功能已经覆盖常用游戏内操作，主要问题是同一窄窗口承载编辑、供应商配置、任务和审核。建议保留鼠标抓取、当前项人工修改、显示层开关、保存后刷新、连接状态和管理员审核入口。供应商高级参数、批量筛选、长文本对照和原文差异适合优先放在网页。待网页端流程经过实机验证后再从 F12 收拢重复入口。服务端下一步优先做可回溯的审核与回执，其次考虑服务端独立运行时的网页管理。
