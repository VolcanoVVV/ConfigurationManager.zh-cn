# 本地网页汉化工作台

同一页面提供「F12 插件设置」和「服务端游戏文本」。首次用游戏导出原文，之后关闭客户端和服务端也能查看快照、人工编辑、调用翻译接口和保存草稿。AI 与机翻仍需能访问所选择的供应商。现有 F12 工作台继续提供游戏内采集、鼠标抓取、管理员审核及发布。

## 启动

在 F12 汉化工作台点「打开网页」，或双击游戏目录 `网页汉化工作台/网页汉化工作台.exe`。本地程序自动打开浏览器，需要 .NET 8 ASP.NET Core Runtime。同一安装的多个标签共用一个服务，关闭最后一个标签后约两秒退出，可以覆盖更新 EXE 和 DLL。刷新页面会接续原有服务。「停止本地网页服务」可让当前安装的服务立即退出。

从旧版升级时先停止旧网页服务，再换用新目录。F12 优先启动「网页汉化工作台」，也能从只有 `WebWorkbench` 的安装启动旧程序。游戏导出的快照、草稿及回执在 `BepInEx/plugins/zh-cn/web-workbench` 下。

从源码运行时使用：

```powershell
dotnet run --project tools/web-workbench/WebWorkbench.csproj -c Release -- "C:\Games\SPT"
```

开发模式下打开 [本地工作台](http://127.0.0.1:17832/)。启动后请在 30 秒内打开页面，终端会在最后一个标签关闭后退出。若端口被占用，可在游戏路径后加一个端口号，再打开终端显示的地址。新版客户端 DLL 要与游戏运行时匹配，替换后需要重启。服务端投稿需要本次配套 SimpleTranslatorCS 构建。

## 离线 CFG 试用

1. 打开网页，点「离线 CFG」，选择一份 UTF-8 的 `BepInEx/config/*.cfg`。导入不需要游戏快照。核对页面识别的插件 GUID，修改 GUID 后点「重新读取」确认。
2. 查看分类、配置名、说明和能识别的枚举候选值。筛选框可缩小试译范围。调用 API 时发送待译字段及其分类、相关说明和匹配术语。实际配置值及默认值注释保留在本机。
3. 在页面查看结果，点「下载 JSONC」取得 `<插件GUID>_API.jsonc`。继续翻译会跳过当前页已成功的字段。译文暂存在本标签页，关闭前先下载。安装到游戏前核对内容并备份同名文件，建议先在没有同名词典的测试插件上试用。

运行时设置、自绘控件和无法确认的候选值可在游戏里用 F12 补采。离线入口只提供下载，游戏目录和现有词典由用户自行管理。

## 操作

1. 在游戏中打开 F12 → 汉化工作台 →「快照与草稿」，按需导出本机 F12 文本或当前服务器的玩家目录。F12 导出范围是当前客户端已收集的原文。安装或更新插件后重新采集，自定义动态文本留在游戏内处理。
2. 在网页选择工作区并刷新快照。F12 预览按插件和配置分类展示名称及说明。点击文字，在右侧修改对应字段，可切换汉化、英文和双语视图。预览根据快照与当前草稿显示文字，实际设置值和游戏内控件由对应插件控制。
3. 顶部「AI 翻译术语表」与游戏内 F12 共用本机词表。网页发起的 F12 和服务端文本 AI 翻译均会附上本批命中的术语。游戏服务器自己执行的 AI 任务仍读取服务端词表。接口翻译用个人供应商密钥，可配置模型、输入输出预算、推理、间隔和重试。
4. 顶部「翻译更新检查」显示已改原文、上次原文及待检查条目，也能切到已有译文或草稿继续校对。F12 原文与插件保存的基准比对。服务端原文与同一连接上一次导出的玩家目录比对，首轮导出用于准备基准，目录可能因审核队列变化而出现新条目。接口翻译完成后进入草稿视图。F12 每份草稿限同一插件和译文层，最多 100 条。服务端每份限 30 条。
5. F12 在游戏中点击「应用网页 F12 草稿」。DLL 校验原文、语境和该译文层的上次值，写入后请求重建设置列表。服务端则点击「预览网页服务端投稿」，核对内容并确认，以当前会话的玩家身份进入审核。正式文本由管理员在现有 F12 工作台审核发布。

服务器切换或客户端重启后需要重新导出服务端目录，再按新目录核对未提交内容。F12 的「刷新网页 F12 快照」发布当前快照。网页的「刷新快照与回执」可立即读取，网页在前台且没有正在编辑的内容或任务时也会每五秒检查一次。游戏内的网页连接面板显示最近的磁盘草稿状态。草稿应用与玩家投稿仍需在游戏内确认。

## 安全边界

- 网页只监听 `127.0.0.1`。校验 Host、Origin、浏览器请求来源和本次进程生成的会话令牌。页面禁止被嵌入，插件原文和译文用纯文本渲染。
- 网页只访问所选安装下固定的工作台快照、草稿和回执。插件负责最终写入译文，当前版本和语境必须匹配。加载内容、运行接口及回填均有大小限制。
- API 密钥仅用于当前本机翻译请求。网页接口不存在管理员登录、文件开关、发布、重载或任意服务端转发。网页投稿由 DLL 绑定当前连接并经游戏界面确认，服务端专用入口强制以玩家身份执行，通过已有玩家档案、开关、冷却和容量校验。
- 当前边界面向浏览器跨站访问及 Fika 玩家权限。它依赖 Windows 用户账户保护本地安装目录。同一 Windows 账户下已经能直接修改游戏文件的进程具备相应的文件访问权限。

## 联动检查与优先级

| 优先级 | 结果或后续工作 | 状态 |
| --- | --- | --- |
| P0 | `manual-exchange` 已对外声明，但 4.0 和新版路由中都缺少 `manual-submit` 注册。旧客户端的人工回填因此可能找不到服务端接口。 | 本轮补齐两套路由，并新增强制玩家身份的网页投稿路由。 |
| P1 | 自动同步曾只检查连接代数，地址或会话已经切换但定时检查尚未更新代数时，迟到结果可能落到新连接的语言表。 | 本轮在接收与主线程应用时重新校验实际连接。 |
| P1 | 原 F12 人工提交先写入，再读取目录，管理员还会继续拉取。写入成功后任一后续读取失败，界面可能报错而让用户误以为未提交。 | 待做。先返回写入回执，再单独记录刷新和同步状态。 |
| P1 | 当前网关以 SPT 玩家档案存在性校验玩家请求。Fika 场景应验证传入会话是否始终绑定真实在线用户，以及玩家提交开关、每人限制和任务归属。 | 待在双客户端环境验证。涉及运营权限的动作继续由服务端独立校验。 |
| P1 | 当前 RequestHandler 身份探测依赖 `Host` 和 `SessionId` 字段。若某个适配器改为属性或采用不同字段，会失去连接绑定。 | 网页投稿在身份不明时拒绝；待对实机适配器补探测和测试。 |
| P2 | 玩家目录由服务端完整发送，网页分页发生在本机。装大量 Mod 时应测量导出时间、传输大小和内存。 | 后续做服务端分页或按来源增量导出。 |
| P2 | 当前网页保留一份草稿，且重新导出后需人工核对旧稿。需要多人或多安装工作流时再增加草稿列表、按原文比对迁移和冲突界面。 | 待做。 |

F12 的功能已经覆盖常用游戏内操作，主要问题是同一窄窗口承载编辑、供应商配置、任务和审核。建议保留鼠标抓取、当前项人工修改、显示层开关、保存后刷新、连接状态和管理员审核入口。供应商高级参数、批量筛选、长文本对照和原文差异适合优先放在网页。待网页端流程经过实机验证后再从 F12 收拢重复入口。服务端下一步优先做可回溯的审核与回执，其次考虑服务端独立运行时的网页管理。
